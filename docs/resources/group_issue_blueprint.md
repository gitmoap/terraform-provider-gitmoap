# gitmoap_group_issue_blueprint (Resource)

Creates a blueprint: a named custom type built on one of the base work-item types, whose facets become acceptance criteria on every work item filed as that type. The repositories and groups beneath the group are offered it too. Its id is a slug, unique in the group. Maintainers and above may define types, up to the group's limit.

The token needs `issue_blueprint:manage` and `issue_blueprint:read`.

## Example Usage

### Basic Usage

```terraform
data "gitmoap_group_by_path" "platform" {
  full_path = "acme/platform"
}

resource "gitmoap_group_issue_blueprint" "incident" {
  group_id     = data.gitmoap_group_by_path.platform.group_id
  blueprint_id = "incident"
  name         = "Incident"
  base_type    = "incident"
  description  = "Something broke in production"
}
```

### Custom work item types

A blueprint is a work item type of the organization's own, built on a base type. Each of its
facets becomes an acceptance criterion on every work item of that type, and a required one has
to be met before the item closes.

```terraform
data "gitmoap_group_by_path" "acme" {
  full_path = "acme"
}

resource "gitmoap_group_issue_blueprint" "api_feature" {
  group_id     = data.gitmoap_group_by_path.acme.group_id
  blueprint_id = "api-feature"
  name         = "API feature"
  base_type    = "story"
  description  = "A change clients of the API can use"

  facets = [
    {
      key      = "docs"
      label    = "Documented"
      category = "documentation"
      hint     = "The OpenAPI spec describes the change"
    },
    {
      key      = "observability"
      label    = "Observable"
      category = "operations"
      hint     = "Dashboards and alerts cover the new endpoints"
      required = false
    },
  ]
}

# New work items are stories unless their author picks another type.
resource "gitmoap_group_issue_settings" "acme" {
  group_id           = data.gitmoap_group_by_path.acme.group_id
  default_issue_type = "story"
}
```

## Schema

### Required

- `base_type` (String) The kind of work item. The type decides where an item may live (a group or a repository), which
types it may have as children, and which fields it accepts.
- `blueprint_id` (String) Blueprint id (slug)
- `group_id` (String) Group ID
- `name` (String) The custom type's display name, such as "API Feature".

### Optional

- `description` (String)
- `facets` (Attributes List) The blueprint's facets, in order. (see [below for nested schema](#nestedatt--facets))

### Read-Only

- `archived` (Boolean) Hidden from the type picker; items already filed keep their `type_profile`.
- `created_at` (String)
- `created_by` (Attributes) Who did something — a person, a service account or an AI organization's agent — with what a
client needs to draw and link them, so a page of records names its actors without a lookup each. (see [below for nested schema](#nestedatt--created_by))
- `scope_id` (String)
- `scope_type` (String)
- `updated_at` (String)
- `version` (Number) The blueprint's revision, incremented on every change. An update must send the version it
read, and is refused with a `409` if the blueprint changed since.

<a id="nestedatt--facets"></a>
### Nested Schema for `facets`

Optional:

- `category` (String)
- `hint` (String) The starter criterion's text. When absent the criterion is titled by the facet `label`.
- `key` (String)
- `label` (String) The facet's display name, such as "Observability".
- `required` (Boolean) Whether the facet's criterion must be satisfied before the work item can be closed or
verified. Defaults to `true`.


<a id="nestedatt--created_by"></a>
### Nested Schema for `created_by`

Read-Only:

- `avatar_url` (String) The principal's picture, when one is known. Absent otherwise: a client derives the
deterministic avatar URL itself.
- `email` (String) The principal's address. An agent's is a generated no-reply address — the author of its
commits. `unknown` on a deleted actor and empty on a redacted one.
- `id` (String) The principal's id: a user id, a service account id or an agent id, as `kind` says. Empty on
a redacted actor.
- `kind` (String) A person, a service account or an AI organization's agent — which of the three a principal is,
and so which page it links to: a person's profile, a service account's page or an agent's page.
- `username` (String) The name to show: a person's or service account's username, or an agent's handle (which
always ends in `-ai`). `deleted-user` when the actor no longer resolves, `redacted` when the
caller may not see who it was. A closed account whose work stays is `closed-` and twelve hex
digits, a shape no open account may take, with an address under `.invalid`.

## Import

Import is supported using the following syntax:

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
# Import by its group_id and blueprint_id, joined with slashes.
terraform import gitmoap_group_issue_blueprint.example "<group_id>/<blueprint_id>"
```

# gitmoap_repository_webhook (Resource)

Registers an HTTPS endpoint that receives a signed JSON `POST` for each event type you subscribe to: `push`, `merge_request`, `issue` or `access`. Every delivery carries an HMAC-SHA256 of its body, computed with the secret you supply, in the `X-Gitmoap-Signature-256` header; the secret is never shown again. The webhook starts active unless you say otherwise, and a repository holds a limited number of webhooks, set by its plan. Maintainers and above.

The token needs `webhook:manage` and `webhook:read`.

## Example Usage

### Basic Usage

```terraform
variable "ci_webhook_secret" {
  type      = string
  sensitive = true
  ephemeral = true
}

data "gitmoap_repository_by_path" "api" {
  full_path = "acme/platform/api"
}

# The secret is write-only: change secret_wo_version to send a new one.
resource "gitmoap_repository_webhook" "ci" {
  repo_id           = data.gitmoap_repository_by_path.api.repository_id
  name              = "ci"
  url               = "https://ci.example.com/hooks/gitmoap"
  secret_wo         = var.ci_webhook_secret
  secret_wo_version = 1
  events            = ["push", "merge_request"]
}
```

### Webhooks whose secrets never reach the state

Each endpoint checks deliveries against a secret. Here the secrets come in through an ephemeral
variable, say from `TF_VAR_webhook_secrets`, and go to gitmoap write-only, so they're in neither
Terraform's plan nor its state (Terraform 1.11 and later). Terraform can't tell when a value it
doesn't keep changes: after changing a secret, change its `secret_wo_version` too.

```terraform
data "gitmoap_group_by_path" "acme" {
  full_path = "acme"
}

variable "webhook_secrets" {
  description = "The secret each endpoint checks deliveries against, by endpoint: ci and chat."
  type        = map(string)
  sensitive   = true
  ephemeral   = true
}

resource "gitmoap_repository" "api" {
  group_id        = data.gitmoap_group_by_path.acme.group_id
  repository_name = "api"
  visibility      = "private"
}

# The CI server builds every push, merge request and tag of the api repository.
resource "gitmoap_repository_webhook" "ci" {
  repo_id           = gitmoap_repository.api.repository_id
  name              = "ci"
  url               = "https://ci.example.com/hooks/gitmoap"
  secret_wo         = var.webhook_secrets["ci"]
  secret_wo_version = 1
  events            = ["push", "merge_request", "tag_push"]
}

# The team's chat hears about merge requests in every repository of the group.
resource "gitmoap_group_webhook" "chat" {
  group_id          = data.gitmoap_group_by_path.acme.group_id
  name              = "chat"
  url               = "https://chat.example.com/hooks/gitmoap"
  secret_wo         = var.webhook_secrets["chat"]
  secret_wo_version = 1
  events            = ["merge_request"]
}
```

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `active` (Boolean) Whether deliveries are sent. Defaults to `true`.
- `name` (String)
- `secret` (String, Sensitive) The secret each delivery is signed with, so your endpoint can check it came from gitmoap.
Stored encrypted and never returned. Or set `secret_wo`, to keep it out of the state.
- `secret_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) Sets `secret` without keeping it in Terraform's plan or state: write-only, with Terraform 1.11 and later. Change `secret_wo_version` to send it again.
- `secret_wo_version` (Number) A number to change when `secret_wo` changes, to send it again: Terraform can't tell, since it doesn't keep it.

### Nested Schema for `created_by`

Read-Only:

- `avatar_url` (String) The principal's picture, when one is known. Absent otherwise: a client derives the
deterministic avatar URL itself.
- `email` (String) The principal's address. An agent's is a generated no-reply address — the author of its
commits. `unknown` on a deleted actor and empty on a redacted one.
- `id` (String) The principal's id: a user id, a service account id or an agent id, as `kind` says. Empty on
a redacted actor.
- `kind` (String) A person, a service account or an AI organization's agent — which of the three a principal is,
and so which page it links to: a person's profile, a service account's page or an agent's page.
- `username` (String) The name to show: a person's or service account's username, or an agent's handle (which
always ends in `-ai`). `deleted-user` when the actor no longer resolves, `redacted` when the
caller may not see who it was. A closed account whose work stays is `closed-` and twelve hex
digits, a shape no open account may take, with an address under `.invalid`.

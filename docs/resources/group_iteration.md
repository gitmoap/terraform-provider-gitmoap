# gitmoap_group_iteration (Resource)

Creates an iteration in the group by hand: a title, an optional description, and the days it runs, both included. Work items from the group and from every repository beneath it can be put in it. Iterations a cadence generates are created for you; this is for one that follows no schedule, such as a hardening week. Maintainers and above may create iterations, up to the group's iteration limit.

The token needs `iteration:manage` and `issue:read`.

## Example Usage

### Basic Usage

```terraform
data "gitmoap_group_by_path" "platform" {
  full_path = "acme/platform"
}

# An iteration that follows no cadence, such as a hardening week.
resource "gitmoap_group_iteration" "hardening" {
  group_id    = data.gitmoap_group_by_path.platform.group_id
  title       = "Hardening week"
  description = "No new features: fix, test and tidy up."
  start_date  = "2027-06-28"
  due_date    = "2027-07-02"
}
```

### Sprints, a milestone, and a hardening week

A cadence keeps two-week sprints created ahead of time. A milestone marks what has to land for a
launch, and an iteration outside the cadence covers the week before it.

```terraform
data "gitmoap_group_by_path" "acme" {
  full_path = "acme"
}

resource "gitmoap_group_iteration_cadence" "sprints" {
  group_id              = data.gitmoap_group_by_path.acme.group_id
  title                 = "Sprint"
  first_start_date      = "2027-01-04"
  start_day             = "monday"
  duration_weeks        = 2
  iterations_in_advance = 3
}

resource "gitmoap_group_milestone" "launch" {
  group_id    = data.gitmoap_group_by_path.acme.group_id
  title       = "Public launch"
  description = "Everything that has to land before launch"
  due_on      = "2027-03-31"
}

# Already behind us. Only an update can close a milestone: the provider creates it, then closes it.
resource "gitmoap_group_milestone" "beta" {
  group_id = data.gitmoap_group_by_path.acme.group_id
  title    = "Private beta"
  due_on   = "2026-12-15"
  closed   = true
}

resource "gitmoap_group_iteration" "hardening" {
  group_id    = data.gitmoap_group_by_path.acme.group_id
  title       = "Hardening before launch"
  description = "No new features: fix, test and tidy up."
  start_date  = "2027-03-22"
  due_date    = "2027-03-26"
}
```

## Schema

### Required

- `due_date` (String) A calendar day, `YYYY-MM-DD`, with no time and no zone — a due date, or the day an iteration starts or ends.
- `group_id` (String) Group ID
- `start_date` (String) A calendar day, `YYYY-MM-DD`, with no time and no zone — a due date, or the day an iteration starts or ends.
- `title` (String) An iteration's title, such as Sprint 24: 1 to 255 characters, with no control characters.

### Optional

- `description` (String) What it is for, in Markdown, up to 16 KiB.

### Read-Only

- `cadence_id` (String) The identifier of an iteration cadence — the schedule that generates a group's iterations.
- `created_at` (String) When it was created, ISO 8601.
- `iteration_id` (String) The identifier of an iteration — a dated container of work in a group, such as a sprint.
- `rollup` (Attributes) How an iteration is going, from the work items in it that you can see. (see [below for nested schema](#nestedatt--rollup))
- `sequence` (Number) Its position in the cadence that generated it, counted from 1. Absent for an iteration
created by hand.
- `state` (String) Where an iteration is in time, read from its dates against today.
- `updated_at` (String) When it last changed, ISO 8601.

### Nested Schema for `rollup`

Read-Only:

- `cancelled` (Number) Those closed without being completed.
- `carry_over` (Number) What carries over: the work items still open, which would carry into the next iteration if
this one ended now, and those already rolled over out of it, which did.
- `carry_over_points` (Number) The points of what carries over — of an item rolled over, the points it left with.
- `committed_points` (Number) The points of every work item in it that is not cancelled — what the iteration took on.
- `completed` (Number) Those completed.
- `completed_points` (Number) The points of its completed work items.
- `open` (Number) Those still open.
- `total` (Number) Work items in the iteration.

## Import

Import is supported using the following syntax:

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
# Import by its group_id and iteration_id, joined with slashes.
terraform import gitmoap_group_iteration.example "<group_id>/<iteration_id>"
```

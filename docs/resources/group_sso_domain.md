# gitmoap_group_sso_domain (Resource)

The response names a TXT record (`_gitmoap-challenge.<domain>`) and the value to publish in it; verify the domain once the record is live. A claim holds nothing until it is verified, so several organizations may claim the same domain and the first to publish its record owns it; claiming a domain another organization has verified is refused, and claiming your own again returns the same challenge. Only the organization's owners claim domains.

The token needs `sso:manage` and `sso:read`.

## Example Usage

### Basic Usage

```terraform
data "gitmoap_group_by_path" "acme" {
  full_path = "acme"
}

# Claim a domain, then prove it with the DNS record the domain's attributes describe.
resource "gitmoap_group_sso_domain" "acme" {
  group_id = data.gitmoap_group_by_path.acme.group_id
  domain   = "acme.com"
}
```

### Single sign-on through an identity provider

The organization signs people in through Okta over OIDC: it claims its domain, connects the
identity provider, and gives it a SCIM token to create and remove accounts. Someone from outside
the domain gets an invite. Once `enforced`, everyone from the domain has to sign in through Okta,
so check the connection works first.

```terraform
data "gitmoap_group_by_path" "acme" {
  full_path = "acme"
}

variable "oidc_client_secret" {
  description = "The client secret of the gitmoap app in Okta."
  type        = string
  sensitive   = true
  ephemeral   = true
}

locals {
  group_id = data.gitmoap_group_by_path.acme.group_id
}

# Proven with the DNS record the domain's attributes describe.
resource "gitmoap_group_sso_domain" "acme" {
  group_id = local.group_id
  domain   = "acme.com"
}

resource "gitmoap_group_sso_connection" "okta" {
  group_id = local.group_id
  protocol = "oidc"

  oidc = {
    issuer_url               = "https://acme.okta.com"
    client_id                = "0oa1b2c3d4e5f6g7h8i9"
    client_secret_wo         = var.oidc_client_secret
    client_secret_wo_version = 1
  }

  attribute_mapping = {
    email    = "email"
    username = "preferred_username"
    groups   = "groups"
  }

  auto_provision = true
  enforced       = true

  depends_on = [gitmoap_group_sso_domain.acme]
}

# Okta creates and removes accounts through SCIM with this token.
resource "gitmoap_group_scim_token" "okta" {
  group_id = local.group_id
  name     = "Okta"
}

output "scim_token" {
  value     = gitmoap_group_scim_token.okta.secret
  sensitive = true
}

# A contractor from outside acme.com, until the contract ends.
resource "gitmoap_group_sso_invite" "contractor" {
  group_id   = local.group_id
  email      = "ada@contractor.example.com"
  reason     = "Payments migration"
  expires_at = "2027-03-31T00:00:00Z"
}
```

## Schema

### Required

- `domain` (String)
- `group_id` (String) The organization's top-level group

### Read-Only

- `status` (String) Whether a claimed email domain has been verified. A `pending` domain has a DNS challenge to
complete; only a `verified` domain links existing accounts or creates new ones at sign-in.
- `verification` (Attributes) The DNS-TXT verification instructions returned when a domain is claimed. (see [below for nested schema](#nestedatt--verification))

<a id="nestedatt--verification"></a>
### Nested Schema for `verification`

Read-Only:

- `method` (String) Always `dns_txt`.
- `record_name` (String) The TXT record name to create (`_gitmoap-challenge.{domain}`).
- `record_value` (String) The TXT record value (`gitmoap-domain-verification=<token>`).

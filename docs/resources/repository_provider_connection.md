# gitmoap_repository_provider_connection (Resource)

Stores, under a name, what a pipeline provider needs to reach an outside service, for use by the repository's pipelines. A connection either holds static credentials, checked against the provider's credentials schema and stored encrypted, or names an identity to assume through OIDC federation, which stores no secret and works only with providers that support it. A connection's name is unique per provider within the repository, and a repository holds a limited number of connections, set by its plan. Answers `501` when this installation has no secret storage configured. Owners of the repository.

The token needs `provider_connection:manage` and `provider_connection:read`.

## Example Usage

### Basic Usage

```terraform
data "gitmoap_repository_by_path" "api" {
  full_path = "acme/platform/api"
}

# Deploys assume a role in AWS through OIDC federation: no secret is stored anywhere.
resource "gitmoap_repository_provider_connection" "aws" {
  repo_id     = data.gitmoap_repository_by_path.api.repository_id
  provider_id = "aws"
  name        = "production"
  auth_mode   = "oidc_federation"
  protected   = true

  federation_target = {
    cloud    = "aws"
    role_arn = "arn:aws:iam::123456789012:role/gitmoap-deploy"
    region   = "eu-west-1"
  }
}
```

### A service account for CI, its token handed to the pipelines

A service account gets the access it needs and no more, and its token is narrowed to one
repository. Terraform hands the token to that repository's pipelines, as a secret variable and as
the credentials of a gitmoap provider connection, both write-only: nobody copies it by hand, and
neither keeps it in the state. When the token is replaced, say with
`terraform apply -replace=gitmoap_service_account_token.ci`, both are replaced with it.

```terraform
data "gitmoap_group_by_path" "acme" {
  full_path = "acme"
}

resource "gitmoap_repository" "api" {
  group_id        = data.gitmoap_group_by_path.acme.group_id
  repository_name = "api"
  visibility      = "private"
}

resource "gitmoap_group_service_account" "ci" {
  group_id     = data.gitmoap_group_by_path.acme.group_id
  name         = "ci"
  access_level = "developer"
}

# The token reads and writes the api repository, nothing else, for 90 days.
resource "gitmoap_service_account_token" "ci" {
  sa_id           = gitmoap_group_service_account.ci.service_account_id
  name            = "ci-api"
  scopes          = ["repo:read", "repo:update"]
  expires_in_days = 90

  resource = {
    scope_type = "repository"
    scope_id   = gitmoap_repository.api.repository_id
  }
}

# Only runs on protected branches and tags receive it.
resource "gitmoap_repository_pipeline_variable" "ci_token" {
  repo_id          = gitmoap_repository.api.repository_id
  name             = "CI_TOKEN"
  value_wo         = gitmoap_service_account_token.ci.token
  value_wo_version = 1
  secret           = true
  protected        = true

  lifecycle {
    replace_triggered_by = [gitmoap_service_account_token.ci]
  }
}

# Pipeline steps that call gitmoap through its provider use the same token.
resource "gitmoap_repository_provider_connection" "gitmoap" {
  repo_id                = gitmoap_repository.api.repository_id
  provider_id            = "gitmoap"
  name                   = "ci"
  auth_mode              = "static_credentials"
  credentials_wo         = jsonencode({ api_token = gitmoap_service_account_token.ci.token })
  credentials_wo_version = 1
  protected              = true

  lifecycle {
    replace_triggered_by = [gitmoap_service_account_token.ci]
  }
}
```

## Schema

### Required

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `auth_mode` (String) How a connection authenticates to its provider's cloud: `static_credentials` (stored
credentials, the default) or `oidc_federation` (nothing stored; each run assumes a cloud role
with a short-lived identity token gitmoap issues).
- `config_overrides` (String) JSON: set it with `jsonencode()`.
- `credentials` (String, Sensitive) The provider's credentials, in the shape its `auth_schema` describes. Required for
`static_credentials`; refused for `oidc_federation`.

JSON: set it with `jsonencode()`. Or set `credentials_wo`, to keep it out of the state.
- `credentials_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) Sets `credentials` without keeping it in Terraform's plan or state: write-only, with Terraform 1.11 and later. Change `credentials_wo_version` to send it again.
- `credentials_wo_version` (Number) A number to change when `credentials_wo` changes, to send it again: Terraform can't tell, since it doesn't keep it.
- `environment_bound` (Boolean) Whether the connection is bound to environments. When it is, only a step deploying to one
of `environment_ids` may use it, and a connection bound only to environments since deleted
is usable by no step.
- `environment_ids` (List of String) Binds the connection to these environments, so only a step deploying to one of them may
use it. Each must be an environment the connection's pipelines can deploy to: one this
group or repository owns, a group above it, or — for a group's connection — a group or
repository beneath it. Leave it out to let any step use the connection. At most 20.
- `federation_target` (Attributes) The cloud role an OIDC-federated connection assumes, identified by `cloud`. `aws` is the only
cloud supported. (see [below for nested schema](#nestedatt--federation_target))
- `protected` (Boolean) Whether only a run on a protected branch or tag may use the connection: one a branch or
tag rule protects, building a commit in that ref's history. Defaults to `false`.
